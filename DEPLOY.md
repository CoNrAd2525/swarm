# RealWorldCerts Deployment & Operations

This guide covers how to build, deploy, and monitor the RealWorldCerts site.

## 1. Secrets Setup (GitHub Actions)

Go to **Settings > Secrets and variables > Actions** and ensure these secrets are set:

### Production (Required)
- `SITE_PUBLIC_URL`: `https://<your-domain>` (only required if you deploy a running site)
- `PAYPAL_OWNER_EMAIL`: `owner@example.com` (only required if you generate PayPal payment links)
- `DEPLOY_HOST`: IP/hostname of your server (only required for SSH deploy workflows).
- `DEPLOY_USER`: SSH user (only required for SSH deploy workflows).
- `DEPLOY_SSH_KEY`: Private SSH key content (only required for SSH deploy workflows).
- `DEPLOY_PATH`: Target directory on server (only required for SSH deploy workflows).

### Staging (Optional)
- `STAGING_DEPLOY_HOST`
- `STAGING_DEPLOY_USER`
- `STAGING_DEPLOY_SSH_KEY`
- `STAGING_DEPLOY_PATH`

## 2. Deployment Workflows

> These are GitHub Actions CI/CD workflows. The agent-driven Base44 workflow fleet
> (Bug Sentinel, Clickless Tick, Critic, Disbursement pipelines) is documented
> separately in [docs/SWARM_WORKFLOWS.md](docs/SWARM_WORKFLOWS.md).

### A. Build Container
**Workflow:** `Site Container Build`
- **Trigger:** Push to `main` or tag `v*`.
- **Action:** Builds Docker image and pushes to `ghcr.io/OWNER/realworldcerts-site:latest`.

### B. Deploy to Server
**Workflow:** `Site Deploy`
- **Trigger:** Manual Dispatch (Go to Actions tab -> Site Deploy -> Run workflow).
- **Inputs:** `environment` (default: `prod`).
- **Action:** 
  1. SSH into server.
  2. Copies `docker-compose.yml`.
  3. Pulls latest image.
  4. Restarts container (`docker compose up -d`).
  5. Verifies `/health`.

### C. Publish Static Artifacts (GitHub Pages)
**Workflow:** `Deploy Static Site to GitHub Pages`
- **Trigger:** Push to `main`/`release`, manual dispatch, and weekly schedule.
- **Action:** Publishes `rank/output` as a static site (schemas, watchdog snapshots, and other safe artifacts).

### C. Watchdog & Monitoring
**Workflow:** `Site Watchdog`
- **Trigger:** Schedule (Hourly) or Manual.
- **Action:** Runs `scripts/site-smoke-test.mjs` against `SITE_PUBLIC_URL`.
- **Checks:** 
  - `/health` (200 OK)
  - `/api/paypal-link` (Valid response)
  - `/feed.xml` (Valid RSS)
  - `/sitemap.xml`, `/robots.txt`
  - Content on core pages.
- **Notification:** Logs failure and intended alert to the configured owner mailbox.

## 3. Local Development & Verification

### Run Locally
```bash
npm run site:start
# Server runs on http://localhost:8080
```

### Generate Feed
```bash
npm run site:feed:gen
```

### Local Smoke Test
```bash
# In a separate terminal while server is running:
npm run site:smoke
```

### Docker Test
```bash
docker build -t site-local -f Dockerfile.site .
docker run -p 8080:8080 site-local
# Check http://localhost:8080/health
```

## 4. Troubleshooting

- **502 Bad Gateway:** Check Nginx logs on server. Ensure container is running on port 8080.
- **404 on Assets:** Ensure `npm run site:feed:gen` ran during build (it is in Dockerfile).
- **PayPal Link Error:** Check `PAYPAL_OWNER_EMAIL` env var in container or secrets.
